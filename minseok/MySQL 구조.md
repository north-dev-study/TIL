## MySQL 서버 5계층 아키텍쳐
### 커넥션 핸들러 (Connection Handler)
- 접속관리, 인증, 스레드 할당
- MySQL은 스레드 기반 모델(thread-per-connection)을 사용, 클라이언트 하나당 스레드 하나를 배정한다. 이 스레드가 해당 클라이언트의 모든 쿼리를 처리한다.
- max_connection 설정 시 웹서버의 갯수도 고려하여 설정해야한다.

### 파서 (Parser)
- 구문 분석 - 문법 규칙 검증
- 파스 트리 - 문법이 올바르면 내부 트리 구조로 변환 후 옵티마이저에 전달

### 옵티마이저 (Optimizer)
- 쿼리를 실행하는 최적의 경로를 결정하는 계층
- MySQL 은 비용 기반 옵티마이저(Cost-Based Optimizer, CBO) - 가장 비용이 낮은 실행 계획 선택
- 어떤 인덱스를 사용할 건지, 테이블을 가져 오는 순서, 어떤 조인 알고리즘을 선택할 건지 결정
- 항상 최적의 선택을 하진 않는다. 통계 정보 부정확시 판단을 잘 못할 수 있다.

### 실행 엔진 (Execution Engine)
- 옵티마이저의 실행계획 수행계층
- 스토리지 엔진과 핸들러 API라는 표준화된 인터페이스를 통해 통신한다.
- 스토리지 엔진에서 행을 가져오고 필터링하고 정렬, 그룹핑 한다.

### 스토리지 엔진(Storage Engine)
- 실제 데이터를 저장하고 읽어오는 계층이다.
- 버퍼 풀을 관리한다.
- 스토리지 엔진을 선택할 수 있다.
- MySQL 기본 스토리지 엔진은 InnoDB이다.
- InnoDB 는 ACID 를 보장하고 행 수준 잠금을 지원(동시성이 좋다)하며 외래 키 지원, 크래시 복구(비정상 종료 후 데이터 복구)를 지원한다.
