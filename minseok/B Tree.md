### B-Tree
- 이진 트리의 단점을 극복하기 위해 나온 자료 구조
- 이진 트리는 한 노드에 데이터 하나와 자식 포인터 2개를 갖고 있는데 디스크의 단위인 페이지(16KB) 에 이것만 담기에는 너무 비효율 적이다.
- 따라서 페이지에 데이터를 꽉꽉 채우기 위해서 이진 트리의 분기 수를 수 십, 수 백배 확장한 자료구조이다.

#### 장점
1. 한 노드에 여러 개의 분기(fan-out) 수를 갖고 있기 때문에 깊이가 얕아진다.
2. 깊이가 얕아진다는 것은 디스크 I/O 가 감소한다는 뜻. (디스크 I/O 비용이 제일 크기 때문에 이것을 줄이는 것이 성능 최적화의 본질이다.)
#### 단점
1. 트리의 모든 노드에 실제 데이터(행 데이터)를 함께 저장한다.
2. 대용량 데이터 처리 시 분기 수가 적어져서 깊이가 깊어진다.

### B+Tree
- B-Tree를 개선하기 위해 나온 자료 구조
- 무거운 실제 데이터를 리프에 몰아 놓고 가벼운 키, 포인터 데이터만 루트, 브랜치 노드에 저장한다.

 - 리프 노드 연결리스트
 - 리프 노드끼지리 서로 이중 연결 리스트로 이어져있다.
 - 하나의 시작점만 알면 노드를 오르락 내리락 하지않고 연결되어 있는 리프로 이동할 수 있다.
 - 실제 데이터를 리프에 몰아 넣어서 가능한 방법
 - 순차 I/O 와 비슷한 구조가 되기 때문에 최적화가 된다.

- 이진 트리의 공간 낭비를 해결하기 위해서 B-Tree 가 등장했고 B-Tree가 무거운 데이터로 인해 트리가 깊어지는 문제를 해결하고자 이정표와 데이터를 분리한 B+Tree가 탄생했다.

### 페이지 분할
- 페이지가 가득 찼을 때 무거운 디스트 I/O 와 락을 수반한 페이지 분할이 발생한다.
1. 새로운 디스크 공간을 할당한다.
2. 데이터의 물리적 이동 > 기존 페이지의 절반을 새로운 페이지로 이동시킨다.
3. 트리구조 업데이터 > 상위 노드에 새로운 페이지의 포인터를 추가한다. 만약 상위 노드도 가득 찼다면 연쇄적 분할이 발생한다.
4. 리두 로그 기록 > 장애 복구를 위해 구조적 변경 사항을 기록 > 디스크 쓰기 발생

#### 페이지 분할 지연
1. Inno DB는 페이지를 15/16 만 채운다.
2. 향후 중간에 Insert, Update로 인한 페이지 분할이 즉시 발생하는 것을 지역시키기 위해서

#### 페이지 병합
- 데이터 삭제로 50% 이하로 페이지가 줄어들면 인접 페이지와 병합을 시도한다. (합쳐서 100% 이하 일때만)

- Inno DB는 연속적으로 값이 증가하는 패턴을 감지하면 페이지를 50:50으로 쪼개지 않고 15/16은 남겨두고 새페이지를 만들어서 데이터를 이어 나간다 > PK를 Auto-Increment 로 해야하는 이유이다.
