View 란 DB 에 쿼리를 저장하고 사용할 수 있는 바로가기 같은 기능이다.
실제 데이터를 저장하는게 아니라서 항상 최신 데이터를 유지한다.
테이블 처럼 사용 가능한게 특징이다. (Where, Order by 등등 사용 가능)
## 장점
1. 편리성, 재사용성
	1. 복잡한 쿼리를 View로 만들어서 테이블 처럼 사용하기 때문에 편리하게 사용할 수 있다.
	2. 하나를 만들어 두면 여러 곳에서 테이블 처럼 재사용하여 사용할 수 있다.
2. 보안성
	1. View 사용 권한을 주어서 원본 테이블 접근을 막을 수 있다.
	2. 민감한 컬럼이나 행을 필터링 하여 제공할 수 있다.
3. 논리적 데이터 독립성
	1. View가 아니라 쿼리를 직접 사용했다면 원본 테이블 변경 시 해당 쿼리를 사용하는 모든 위치에서 쿼리 수정이 필요하지만 View 사용시 View만 변경하면 문제가 없다.
	2. 충격을 완화하는 추상화 계층 역할을 한다.

## 단점
1. 성능 문제
	1. 사용하기 간단해서 함부로 사용하기 쉬운데 그 안에는 복잡한 쿼리가 숨겨져 있어서 성능이 나오지 않을 수 있다.
	2. View 안에 View 를 사용할 경우 옵티마이저가 실행계획을 제대로 세우지 못 해 성능 저하가 있을 수 있다.
2. 업데이트 제한
	1. 복잡한 Join, 집계 쿼리일 경우 Insert, Update, Delete가 제한된다.
	2. 기본적으로 View는 '조회'전용으로 사용해야한다.
