## Index 란?
- 특정 컬럼을 정렬해서 저장하고 이를 통해 원본 데이터에 빠르게 접근할 수 있는 특별한 목차이다.

### Full Table Scan
1. 데이터 조회가 느려지는 원인이다.
2. 말 그대로 테이블을 처음부터 끝까지 전부 조회하는 것이다.
3. 디스크 IO 병목현상이 일어날 수 있다.
4. O(n) : Big O 데이터가 늘어날 수록 비례해서 느려진다.

### Full Table Scan 방지 실무적 관점
1. 인덱스 활용
	1. Where 절에 자주 사용하는 컬럼에 Index를 생성한다.
2. 실행계획 확인
	1. 의도치 않은 Full Table Scan 이 발생하는지 확인한다.
3. 작업시간 분리
	1. 대용량 데이터 Full Table Scan이 필요할 경우 새벽 시간을 이용한다. (새벽에 실행되는 쿼리 작성)

### 트리 자료 구조
- 트리는 부모 노드와 자식노드로 구성된다.

1. 이진 탐색 트리
	1. 왼쪽 자손이 더 작은 값을 가지고 오른쪽 자손이 더 큰 값을 가진다.
	2. 한 번에 탐색할 절반을 날려 버린다.
	3. O(log n) 
	4. 데이터의 크기가 클 수록 효과적이다.
	5. ★데이터를 정렬한 상태로 보관해두어야 한다!
	6. 최악의 경우 Full Table Scan과 동일하다. > 이를 보완하기 위해 밸런스 트리 등장
	7. 인덱스에 쓰이는 B-Tree는 밸런스 트리의 한 종류
2. 순회
	1. 중위순회
		1. 같은 방향으로만 노드를 처리한다.
		2. ex) 왼쪽 노드를 처리하고 원래로 돌아온다
		3. 오름차순, 내림차순 구현가능하다.

### PK, FK, Unique Key
1. 이 제약조건들은 자동으로 인덱스를 생성한다.
2. PK와 FK는 그렇다 해도 Unique Key는 왜? > 테이블에 Insert 나 Update 하려는 값이 중복되었는지 조회를 해야하기때문이다.

### 실행계획
- Explain [쿼리]

1. type
	1. ALL : Full Table Scan
	2. ref : =, join 과 같은 동등 조건에서 인덱스 사용
	3. range : between, >, < 과 같은 범위 조건에서 인덱스 사용
2. key
	1. 쿼리를 실행할 때 사용한 인덱스
3. rows
	1. 탐색할 것으로 예상되는 행의 수
4. filtered
	1. 조건에 의해 필터링 되고 남을 비율
5. Extra
	1. Using where : 데이터를 가져온 후에 where 사용
	2. Using index condition : 인덱스 사용

### 범위 조건
- 처음 하나만 이진 탐색으로 찾고 그 이후는 연속적으로 탐색한다 (정렬되어있기 때문에 가능하다)

### 정렬
- 비용을 많이 잡아먹는 작업이다.
- Order by 에 인덱스 컬럼을 사용할 경우 옵티마이저가 정렬 작업을 생략해버린다 (인덱스 자체가 원래 정렬되어 있기 때문에)
- 단일 컬럼 인덱스에선 역방향도 가능하다.
- 정방향 스캔이 역방향 스캔보다 미세하게 빠르다. (컴퓨터 하드웨어의 미리읽기 때문)
- 내림차순 인덱스를 만들 수 있다. (단일 컬럼 인덱스는 큰 차이 없다)
- 복합 인덱스에선 오름차순, 내림차순 인덱스가 중요해진다. (정렬 순서도 이에 맞게 적용해야 인덱스 효과를 본다.)

### LIKE
- 와일드 카드가 맨 뒤에 위치해야 인덱스를 사용할 수 있다.
- 와일드 카드 앞 부분만 이진 탐색하고 그 이후로는 범위 조건과 같이 연속적으로 탐색한다.
- 와일드 카드가 앞에 있으면 Full Table Scan이 일어난다.
- 필요한 경우 Full - Text Seach 라는 전문 검색 기능 적용
