## 트랜잭션이 생긴 이유

### 데이터 동시 접근의 문제
- 하나의 데이터에 여러 사용자가 동시에 접근하게되었을때 데이터 일관성이 훼손될 수 있다.
- 데이터의 일관성, 무결성을 지키기 위해 작업처리순서를 일부 조정해야한다.


## 트랜잭션 개념

- 데이터베이스를 조작하기 위한 하나의 논리적 단위를 이루는 일련의 데이터베이스 연산의 집합
ex) 예금 인출 : read - 연산 - write

핵심 : 하나의 작업목표를 수행하기 위한 연산의 묶음 단위!


## Read / Write

- Read : 데이터베이스의 값을 읽어 트랜잭션 메모리에 저장한다.
- Write : 트랜잭션의 값을 데이터베이스에 저장한다.

```
ex) 계좌 A에서 B로 1000원을 이체하는 트랜잭션

Read(A)
A := A-1000
Write(A)
Read(B)
B := B + 1000
Write(B)
```


## 특징

### ACID : 다수연산을 단일 작업처럼 다뤄지도록 하기위해!

Atomicity 원자성 : 다 되거나, 다 안되거나
Consistency 일관성 : 트랜잭션 실행 전과 후의 DB 상태가 일관된다
Isolation 고립성 : 트랜잭션 작업 중 다른 트랜잭션의 방해를 받지 않는다.
Durability 지속성 : 실행 완료 후에는 그 결과는 지속된다.


## 트랜잭션 실행 연산자
### commit
: ~을 수행하다. 갱신된 데이터를 DB에 반영. 지속성 확보

### rollback
: 트랜잭션이 중단되기 이전까지 진행된 데이터 변경값을 무효화함. 일관성 확보



## 트랜잭션 동시 실행 :: 동시성 제어

- 유휴자원을 활용하기 위해 여러 트랜잭션을 돌린다. > 트랜잭션 처리율 / 자원 이용률 향상
- 트랜잭션 대기 시간 감소

-> 일관성이 훼손되지 않는 선에서 최대한 동시 실행함


## 스케쥴

- 다수의 트랜잭션에 포함된 연산의 실행 순서를 명시한 것
- 여러 트랜잭션을 실행할 때, CPU는 하나니까,,, 어떤 순서로 어떻게 처리할건지? 가 스케쥴임

### 직렬 스케쥴
트랜잭션 1 -> 트랜잭션 2
- 한 트랜잭션이 모두 완료되고 난 후 다음 트랜잭션이 실행됨
- 일관성은 문제가 없다.
- 순차 실행

### 병렬 스케쥴
트랜잭션 1-1 -> 트랜잭션 2-1 -> 트랜잭션 1-2 > 트랜잭션 2-2
- 하나의 트랜잭션이 완료되기 전 다른 트랜잭션이 실행됨
- 일관성 훼손 가능성 있음
