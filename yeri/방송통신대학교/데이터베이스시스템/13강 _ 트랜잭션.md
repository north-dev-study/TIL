- 데이터베이스 시스템도 전체 작업을 하기 위해 내부에 작은 명령으로 나뉘어져있다.

## 트랜잭션이 생긴 이유

### 데이터 동시 접근의 문제
- 하나의 데이터에 여러 사용자가 동시에 접근하게되었을때 데이터 일관성이 훼손될 수 있다.
- 데이터의 일관성, 무결성을 지키기 위해 작업처리순서를 일부 조정해야한다.


## 트랜잭션 개념

- 데이터베이스를 조작하기 위한 하나의 논리적 단위를 이루는 일련의 데이터베이스 연산의 집합
ex) 예금 인출 : read - 연산 - write

핵심 : 하나의 작업목표를 수행하기 위한 연산의 묶음 단위!


## Read / Write

- Read : 데이터베이스의 값을 읽어 트랜잭션 메모리에 저장한다.
- Write : 트랜잭션의 값을 데이터베이스에 저장한다.

```
ex) 계좌 A에서 B로 1000원을 이체하는 트랜잭션

Read(A)
A := A-1000
Write(A)
Read(B)
B := B + 1000
Write(B)
```


## 특징

### ACID : 다수연산을 단일 작업처럼 다뤄지도록 하기위해!

Atomicity 원자성 : 다 되거나, 다 안되거나
Consistency 일관성 : 트랜잭션 실행 전과 후의 DB 상태가 일관된다
Isolation 고립성 : 트랜잭션 작업 중 다른 트랜잭션의 방해를 받지 않는다.
Durability 지속성 : 실행 완료 후에는 그 결과는 지속된다.


## 트랜잭션 실행 연산자

### rollback
: 트랜잭션이 중단되기 이전까지 수행한
